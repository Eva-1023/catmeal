# 固定机位猫咪进食统计：第一阶段方案

## 输出定义

基本单位是事件，而非帧。建议交付三类统计：

1. 到访事件：猫在喂食器到访区域出现、按时间间隔合并后的记录。
2. 进食候选：事件内猫掩码覆盖进食区域，并累积足够的相邻检出时间。
3. 确认进食：复核动态证据确认吃饭后，单独计入 confirmed_feeds。

每个事件包括开始/结束时间、日期/时区、临时轨迹编号、毛色建议及投票、实际证据时长、帧数、源录像、证据截图、歧义标记、复核结果。按毛色汇总与按个体汇总分开；后者只接受人工身份标签。

## 流程

原始视频 → 清单真实时间/去重 → PTS 顺序解码 → 每秒 2 帧 → 猫实例分割 → 到访与进食区域覆盖 → 毛色建议 → 一对一空间关联 → 事件状态机 → 证据与日报 → 人工复核。

为避免跟踪器在抽帧后把 frame buffer 错当真实秒，当前基线使用匈牙利一对一关联、归一化框中心距离、框 IoU 和已知粗毛色门限。关联状态按秒过期。该规则适合先做可解释基线，不能保证多猫交叉时身份稳定。

事件打开后，保持到最后一次在到访区域的检出；短暂离开保留同一候选，超过合并间隔才关闭。跟踪到猫在区域外时不累计进食证据；缺少该猫检出的采样也不累计。多个检测框不会合并成一个“食盆占用次数”。视频连续分片使用同一时轴；超过观测缺口阈值时关闭并标记，而不假装缺口内猫已经离开。

## 毛色路线

第一阶段只用分割掩码内部的 HSV 分布提供保守建议。掩码腐蚀后取色减少背景污染；近黑白画面禁用毛色判断。阈值未经本站点校准，光线变化、遮挡、IR 滤镜切换仍可能影响分类。

拿到录像后，优先建立每只已知猫的日间参考图和独立验证图，再决定是否需要训练小型分类器或使用局部外观特征。花纹/三花/狸花依赖空间结构，仅凭全局色彩比例不能可靠区分。夜间身份若要追溯，必须有可靠的连续轨迹或独立依据；否则保留未知。当前代码不包含未验证的跨日 ReID 模型。

## 首批视频校准

建议从实际可用录像中抽取白天、夜视、黄昏切换、有猫/无猫、猫只路过、长时间吃饭、短暂离开又回来、多猫同框等场景。先手工标注部分事件，用一部分调参，保留其他连续片段验收，避免用同一事件的相邻帧同时调参和验收。

1. 确认导出格式、原始时间来源、时区、单段长度和分片是否重叠；核对开头、中部、结尾画面水印，排查时钟漂移。
2. 标注到访和进食区域，查看检测结果是否包括猫而没有稳定漏检；猫太小或遮挡严重时，比较更大模型、局部裁剪或标注微调。
3. 与用户共同冻结“进食一次”的操作定义：路过是否排除、短暂离开阈值、舔食残渣是否计次、两只猫同时吃的处理。
4. 对抽样频率 1/2/4 fps、最短证据 2/3/5 秒、合并间隔 30/60/120 秒做同输入敏感性比较。只改变事件参数可重放检测；改变抽样/ROI/模型必须重跑。
5. 逐条复核漏检、误报、错误拆分、错误合并、毛色未知和错误身份关联；不能只比较每日总数，因为多计和漏计可能互相抵消。

## 验收要记录的指标

- 事件检出 precision / recall；匹配需同时间窗口且同可确认个体，不能只靠相同毛色。
- 每日计数绝对误差，拆分次数、合并次数、误报和漏报各自数量。
- 事件开始/结束偏差和边界截断比例。
- 在可判断的日间样本上的毛色分类准确率及混淆表；另列未知比例、夜视覆盖率。
- 多猫/遮挡分组结果；不同光照分组结果。
- 录像实际覆盖时长、断片数、失败文件、重复与重叠拒绝记录。
- 处理速度、峰值内存、截图/检测日志大小；用真实 1080p/2K 视频实测后再估算全天运行成本。

具体验收目标在真实样本到位、行为定义确认后冻结。当前测试验证程序逻辑和运行链路，不构成目标场景准确率验收。

## 明确留待下一阶段

- 基于真实样本的日期清单自动生成与必要的水印 OCR。
- 猫头/进食姿态识别或监督行为分类，减少仅凭 ROI 停留产生的误报。
- 本机位毛色/花纹参考集与分类器。
- 复杂遮挡、多猫交叉情况下更强的跟踪和身份复核。
- 页面内手动合并/拆分事件；当前可通过复核标记、阈值重放处理可表达的错误。
- 长录像增量处理、断点续跑、事件截图存储压缩。当前按新 run 完整重跑；CPU 为已选默认路径，MPS 需另测。

这些工作依赖真实视频，不在空数据上假装已验证完成。
