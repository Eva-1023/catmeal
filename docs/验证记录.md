4. **真实模型 + 合成 MP4 的完整链路通过**：将公开双猫静态图片放入 10 秒测试视频，前后各 2 秒为空白，中间 6 秒为同一静态画面。默认 2 fps 共采样 20 帧，得到 24 条猫检测，最终合成 2 个事件，每个 12 条检测、5.5 秒相邻检出证据。由于测试故意把整张图当 ROI，产生的“进食候选”仅用于验证数据流，**不是猫在吃饭**。人工确认次数保持为 0。
5. **事件规则演示通过**：601 个合成采样时刻，4 次到访，3 次进食候选（橘色 2、黑白 1），未知色短暂到访 1，人工确认 0。见 `outputs/demo`。
6. **输出文件核验通过**：解析 HTML，核对每个引用的 CSV、截图和 MP4 文件存在；证据 JPEG 可读并已查看；导出事件 MP4 可完整解码为 80 帧，时间范围 0–9.875 秒，并已查看其中的时间字幕画面。

## 本机环境

- macOS 26.5.2，Apple Silicon arm64。
- 独立 Python 3.12.13 虚拟环境 `.venv`。
- Ultralytics 8.4.172、PyTorch 2.14.1、TorchVision 0.29.1。
- PyAV 16.1.0、OpenCV 4.11.0.86、NumPy 2.5.3、SciPy 1.18.1。
- CPU 推理已验证。检测到 MPS 可用，但尚未验证 MPS 的这条分割流程。
- PyAV 自带 FFmpeg 解码/编码库，无需系统级 ffmpeg。

OpenCV 5.0 曾与 PyAV 加载重复的 macOS AVFoundation 组件；固定为 OpenCV 4.11.0.86 后导入和上述测试不再出现该冲突提示。首次端到端测试发现 NumPy 布尔值不能直接写入 JSON，已转成 Python bool 并增加回归测试。失败运行单独保存在 `outputs/smoke-analysis-failed-01`，成功运行在 `outputs/smoke-analysis`。
