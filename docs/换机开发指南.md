# 换机开发指南

本指南对应 2026-10-15 整理的项目。推荐使用 Python 3.12。现有精确锁文件来自 macOS Apple Silicon；其他平台使用项目依赖范围安装，需要重新验证。

## 1. 克隆仓库

```sh
git clone https://github.com/Eva-1023/catmeal.git
cd catmeal
```

这是私有仓库，新机器需要先使用有权限的 GitHub 账号登录 Git 或 GitHub CLI。不要将 GitHub 凭据写进项目文件。项目可放在任意目录，无须重建旧机器的 `/Users/liyi/Projects/猫猫视频分析` 路径。

## 2. 安装与验证

### macOS Apple Silicon：恢复锁定环境

先准备 Git 和 uv（已有 Homebrew 时可运行 `brew install uv`），然后运行：

```sh
sh scripts/bootstrap.sh
```

脚本会用 uv 创建 Python 3.12 虚拟环境、同步 `requirements-macos-arm64.lock.txt`、以可编辑方式安装项目、下载模型并进行空白图推理、输出环境检查，最后运行测试。不要复制旧机器的 `.venv`；其中包含绝对路径和平台相关文件。锁文件中的版本如在目标软件源不可用，应先记录安装错误，再决定是否单独建立新环境；不要悄悄升级后称为精确复现。

### Linux / Intel Mac：建立新的开发环境

先安装 Python 3.12，然后运行：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/catmeal prepare
.venv/bin/catmeal doctor --out outputs/environment.json
.venv/bin/python -m pytest -q
```

### Windows PowerShell：建立新的开发环境

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\catmeal.exe prepare
.venv\Scripts\catmeal.exe doctor --out outputs/environment.json
.venv\Scripts\python.exe -m pytest -q
```

Windows 安装会带上 `tzdata`，供 `Asia/Shanghai` 时区使用。Linux、Intel Mac、Windows 的环境没有在此次迁移中执行实机验证；上面的安装按项目声明的依赖范围解析，不保证与 macOS 锁文件逐项一致。先使用 CPU。GPU/CUDA/MPS 配置属于后续独立验证。

`catmeal prepare` 会生成 `models/yolo11n-seg.pt` 和本机 `models/model_info.json`。后者不跟踪到 Git，避免每次运行改变提交。历史模型哈希保存在 `models/model_info.reference.json`：

```text
55ed65c56c91713d23e8402371c6c49a6fd84f257f7dce452e8d70e41dcbe152
```

需要延续历史模型时，应对比新下载文件的 SHA-256；不一致时先保留差异并检查来源。离线机器可以手动复制旧机器的权重到同一路径。空白图推理只检查加载和执行能力，不验证检测准确率。

## 3. 不依赖原始录像的演示

在仓库根目录执行（Windows 使用对应的 `.venv\Scripts\` 程序）：

```sh
.venv/bin/python scripts/make_demo.py
.venv/bin/catmeal replay --observations outputs/demo-input/observations.jsonl --config config.example.json --out outputs/demo
```

用浏览器打开 `outputs/demo/report.html`。预期为 4 次到访、3 次进食候选、0 次人工确认。重复执行时请改用新的输出目录，程序不会覆盖已有 run。此演示仅验证事件和报告流程。

普通录像的 ROI 标注、清单填写、分析和复核步骤见主 README。`config.example.json` 和 `manifest.example.csv` 是模板；本机使用的 `config.json`、`manifest.csv` 已加入忽略规则。ROI 页面生成的配置可能带模型绝对路径，换机时应改为相对配置文件的 `models/yolo11n-seg.pt` 或新机器的实际路径。

## 4. 加速屏幕录制专用流程

加速录屏必须读取画面里的摄像头时间；不能直接将录屏 PTS 当作真实事件时间。此流程与普通录像的 `catmeal analyze` 分开，见 [屏幕录制分析方法](屏幕录制分析方法.md) 及各日期分析记录。

### macOS 工具准备

目前水印 OCR 使用 Apple Vision，仅支持 macOS；需要系统 Swift 编译器（缺少时安装 Xcode Command Line Tools）。从仓库根目录编译：

```sh
mkdir -p outputs/real-analysis
swiftc scripts/ocr_clock.swift -o outputs/real-analysis/ocr_clock
```

`scripts/run_clock_ocr.py` 固定从这个位置调用编译程序，即便分析其他日期也需要先编译一次。二进制不随 Git 迁移。历史绘图脚本还使用 `/System/Library/Fonts/STHeiti Medium.ttc`；Linux/Windows 需替换 OCR 实现、中文字体路径并另行测试，不能直接照搬整条录屏流程。

### 已保留的历史配置

以下目录保留 `analysis-config.json`、已有 `run.env`、人工复核的 `visual-review.json`、候选编号 `proposals.json`，以及存在时的时钟修正/异常说明和 `anchor-*.png` 跟踪模板：

| 录像日期 | 配置目录 | 最终交付目录 |
|---|---|---|
| 2026-10-03 | `outputs/real-analysis/` | `outputs/final-2026-10-03/` |
| 2026-10-04 | `outputs/real-analysis-2026-10-04/` | `outputs/final-2026-10-04/` |
| 2026-10-05 | `outputs/real-analysis-2026-10-05/` | `outputs/final-2026-10-05/` |
| 2026-10-06 | `outputs/real-analysis-2026-10-06/` | `outputs/final-2026-10-06/` |

`data/reference/` 保留日间和夜间参考图。上述历史标注只对应原来的录像、抽帧编号与参数，不可用于新录像。第三、第四段的跟踪锚点按脚本要求保留在各自分析目录。配置里的区域坐标需要结合脚本核对；部分代码仍使用本机位固定坐标，不能认为改一个 JSON 就完成了新机位适配。

例如查看第四段配置可使用 `source outputs/real-analysis-2026-10-06/run.env`，但完整重新运行还需要恢复下节所列原视频和中间数据。不要在已有历史结果目录上直接重跑。新录像应复制适用的配置和锚点到新目录，修改 `CATMEAL_ANALYSIS_DIR`、`CATMEAL_FINAL_DIR`、`CATMEAL_IMPORT_DIR`、`CATMEAL_VIDEO`、`CATMEAL_DATE`，重新核对区域并生成新的复核记录。

### iPad 导入脚本

`scripts/import_ipad_video.py` 是依赖已有设备资产清单的专用工具，不是完整的自动找视频向导。它还需要：

- 单独安装并验证 `pymobiledevice3`（未纳入主锁文件），以及已配对、可信任的 USB iPad。
- 设置 `CATMEAL_IPAD_UDID` 为目标设备标识；源代码不再绑定旧设备。
- 在 `CATMEAL_IMPORT_DIR` 下准备 `long_video_candidates.json`，其第一项必须是核对过的待导入资产，包含 `directory`、`filename`、`original_filename`、`original_size`。

也可通过其他途径复制原始录像，再建立对应来源和哈希记录。不要用转码副本冒充原始文件。

## 5. Git 包含范围与额外数据迁移

Git 包含全部 Python/Swift/脚本代码、测试、依赖与安装配置、全部项目说明、配置模板、历史运行设置和复核标注、参考图，以及四段最终报告、CSV/JSON、统计图和 525 张证据图。保留历史相对路径，克隆后可以直接在浏览器里打开 `outputs/final-*/report.html`。GitHub 文件预览不执行本地 HTML 报告的交互功能。

以下内容不放进代码仓库：

| 内容 | 恢复方式 |
|---|---|
| `.venv/`、缓存、Python 编译缓存 | 在新机器重新安装或生成 |
| `models/*.pt` | `catmeal prepare` 下载，或单独复制并核对哈希 |
| `data/videos/` 原始视频 | 从 iPad 或备份重新复制；本地四段原视频此前已清理 |
| 大量中间抽帧、检测、水印 OCR、时间轴、导入审计等 | 需要继续历史分析时额外迁移旧机器 `outputs/` |

仅查看既有最终报告不需要原视频；重新分组/生成历史证据报告通常需要中间数据；重新解码和源文件完整 SHA-256 校验还需要原视频。历史 `validation.json`、`status.json`、`provenance.json` 是原运行留下的证据，不能当作新机器重新验证的记录。

需要保留全部现有工作数据时，在旧机器仓库根目录创建额外迁移包（约数 GB，实际以当时文件为准）：

```sh
tar -czf ../catmeal-working-data.tar.gz outputs data/reference
shasum -a 256 ../catmeal-working-data.tar.gz
```

将包和哈希值通过移动硬盘或其他文件传输方式移到新机器，核对哈希。先解压到单独暂存目录再合入项目，避免覆盖新机器已经开展的工作。包中的导入记录或生成配置可能带旧机器绝对路径，按用途调整工作副本并保留原始审计文件。该迁移包不会自动生成或推送到 GitHub。

## 6. 后续开发约定

- 先运行现有测试和无视频演示，再用单独的小样本验证视频/模型改动。
- 事件按时间连续性合并；检测帧数不等于进食次数。颜色不等于身份，夜视结果保留不确定性。
- 保持原始候选、人工复核和最终统计的来源可追踪；不把有限覆盖说成完整全天。
- 每次分析使用新输出目录。新增有保留价值的配置或交付产物时，明确更新 `.gitignore` 的允许清单并检查暂存内容。
- 不随意改动历史验证记录。更换参数、模型、脚本或来源后，创建新结果并重新验证。
