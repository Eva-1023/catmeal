## 已准备的功能

- YOLO11n 实例分割提取猫和猫身上的像素，避免直接用含背景的矩形估计毛色。
- 按视频 PTS 时间戳抽样，默认每秒 2 帧；支持可解码的 MP4/MOV/MKV 等容器和可变帧率。PyAV 自带 FFmpeg 库，不要求系统安装 `ffmpeg` 命令。
- 离线浏览器拖动标注两个矩形：到访区域、食盆/猫头进食区域。
- 根据空间关联和粗毛色维护临时轨迹，多猫一对一匹配；时间状态机合并同一次到访。
- 每个事件保留时间、累计进食区域证据、源视频、截图、毛色投票和复核标记。
- 输出事件 CSV、每日统计 CSV、录像覆盖 CSV、HTML 复核页、原始检测 JSONL、实际配置、模型/输入文件哈希。
- 可导出有时间字幕的静音事件 MP4；可修改复核 CSV 后重新统计。
- 可重放已有检测结果，调整事件合并间隔和最短停留，无须重跑模型。

## 视频到位后的操作

### 1. 放入视频，标注区域

将录像复制到 `data/videos/`，保留原件和原始名称。先选一段看得清喂食器的录像：

```bash
.venv/bin/catmeal roi --video data/videos/第一段.mp4 --at 10
open outputs/roi.html
```

在页面拖出绿色到访区域，再拖出橙色进食区域，后者必须位于前者内。下载 `config.json`，放在项目根目录。页面会保留已解析的模型绝对路径。

食盆区域要尽量包含猫头进食时的位置；身体或尾巴盖住食盆仍可能形成候选，需要真实例子调参。不要简单框住整个房间。

### 2. 提供真实录像起始时间

复制 `manifest.example.csv` 为 `manifest.csv`，填写每个文件**第一张解码画面**对应的真实时间：

```csv
path,start_time,camera_id
data/videos/20261003_080000.mp4,2026-10-03T08:00:00+08:00,xiaomi_feeder_1
data/videos/20261003_080100.mp4,2026-10-03T08:01:00+08:00,xiaomi_feeder_1
```

相对路径以清单所在目录为基准；时间必须含时区。同一批只处理一个机位。不会把复制时间/文件修改时间当拍摄时间，不假定所有小米文件名都具有同一规则。拿到样本后先核对文件名、画面时间水印、时区和时钟偏移，再按确认的规则批量生成清单。当前不自动 OCR 水印。

### 3. 分析并复核

```bash
.venv/bin/catmeal analyze --manifest manifest.csv --config config.json --out outputs/run-001
open outputs/run-001/report.html

# 导出单次到访的动态证据；省略 --event 会导出全部。
.venv/bin/catmeal clips --run outputs/run-001 --event E000001
```

导出片段是 8 fps 静音采样预览，带原始时间字幕；遇到可变帧率，预览播放节奏可能与原视频略有差异，统计时间以原始 PTS 为准。原视频和截图保留完整来源。

每个 run 必须是新的目录，防止覆盖已有结果。首次建议只给 10–30 分钟含猫录像。长视频要顺序解码，2 fps 只减少模型推理，不代表可以省去视频解码成本。截图保存所有目标区域内采样检出，方便重放审计；长时间有猫的录像会使用较多磁盘空间。

在 `review_template.csv` 的副本 `reviews.csv` 填写：

| 列 | 含义 |
|---|---|
| event_id | 原事件编号，不能修改 |
| decision | `confirmed` 确认进食；`not_feeding` 非进食；`uncertain` 无法判断；`unreviewed` 未复核 |
| corrected_color | 可选：`orange`, `black`, `white`, `black_white`, `gray`, `tabby`, `calico`, `tortoiseshell`, `other`, `unknown` |
| cat_id | 可选：人工确认的个体编号；同毛色不能自动视为同一只 |
| notes | 复核说明 |

```bash
.venv/bin/catmeal report --run outputs/run-001 --reviews outputs/run-001/reviews.csv
```

原始事件和检测保持不变，复核后统计独立写出。重复生成报告会保留上次应用的复核结果。复核 CSV 当前支持确认/排除和毛色、个体纠正；**手动拆分或合并事件尚未实现**。遇到此类错误应保留说明、调整事件参数重放或修正检测序列，并建立新 run，不能把未经校正的候选总数当作最终进食总数。

### 4. 调整时间规则

```bash
.venv/bin/catmeal replay --observations outputs/run-001/observations.jsonl --config config.json --out outputs/replay-gap30
```

重放只重算轨迹关联/事件规则，`sample_fps`、检测阈值、ROI 和颜色规则的改变需要重新分析视频。重放生成新的事件编号，必须重新复核，不可直接套用旧复核表。重放结果的截图引用原 run，须保留原目录。

## 统计规则与默认参数

| 参数/规则 | 默认 | 意义 |
|---|---:|---|
| sample_fps | 2 | 每秒约 2 个采样时刻；帧数不当次数 |
| confidence | 0.30 | 猫检测阈值，须用本机画面校准 |
| roi_overlap | 0.05 | 猫掩码占相应 ROI 面积至少 5% |
| min_feeding_seconds | 3 | 在进食 ROI 内相邻检出的时间间隔累计至少 3 秒，才是进食候选 |
| merge_gap_seconds | 60 | 同一临时轨迹离开到访区域 **超过** 60 秒再出现，算新事件；短于/等于此值可合并 |
| max_observation_gap_seconds | 1.5 | 超过此长度没有采样记录，视为录像/观测缺口；不能跨缺口确认行为连续 |
| track_distance | 0.15 | 相邻关联允许的归一化中心距离上限之一；结合框重叠和粗毛色 |
| color_mode | auto | 全画面近黑白时拒绝判断颜色；可明确设 `night` 或 `day` |
| 每日归属 | 开始日期 | 跨午夜事件只计一次，覆盖时长按日期切开 |

60 秒和 3 秒只是起始参数，不是猫咪行为的固定标准。后续用你的猫和喂食器确定“抬头/短暂离开”和“又来吃了一次”的分界。

“累计进食区域证据”仅累积相邻有效检出的间隔，漏检、离开区域和录像缺口不补成进食时间。事件跨度包含短暂离开，所以跨度与证据时长分列。

## 结果边界

- **出现、靠近食盆、实际吃饭是不同证据层级。** 目前检测器识别猫，ROI + 停留时间生成进食候选；没有训练专门的猫头姿态/吞咽行为模型。最终确认进食依赖动态证据复核。
- **颜色不等于身份。** 自动只建议橘、黑、白、黑白；灰猫、狸花、三花等先保留未知，经真人标注后再建立本站点分类器/参考图集。短时轨迹编号不能用于识别跨天同一只猫。
- **夜视不猜毛色。** 红外图像可能把黑毛变浅；未知类照常计事件。`auto` 只是近黑白启发式，切换灯光或夜视有彩色叠字时可误判，需校准或指定 `night`。
- **多猫交叉、遮挡、毛色波动可能使轨迹断裂或串号。** 所有事件都可复核；`multiple_cats`, `ambiguous_tracking`, `reassociated_after_absence` 等标记提示优先检查。相同颜色的替换在单目画面中可能无法区分。
- **录像缺口不等于猫离开。** 程序保守拆分并标记 `recording_gap` / `left_boundary` / `right_boundary`；由此产生的片段可能属于同一次真实进食，需要复核。连续文件可自然拼接；时间重叠会报错，重复文件/副本会拒绝。
- **每日次数只代表提供的录像。** 事件触发录制、断网缺片、没有覆盖全天，都不能报告成完整全天次数。`coverage.csv` 给出实际采样记录之间的覆盖时长（不含未知首尾、末尾不足采样间隔）；不自动认定全天完整。没记录的日期不能补 0。
- **解码失败不产出成功结论。** run 状态置为 failed；保留部分检测供排查。更换分辨率需要重新标注并分开分析。加密导出文件需先从小米官方途径导出可播放录像。
